# Web UIの実装

## コンポーネントと配置

- 用途に合うBasecoatの標準コンポーネントを使います。配色・角丸・影・文字の太さなどもカスタマイズせず、標準のままで使います。
- 用途に応じて標準variantを選び、hover・focus・disabledなどの状態表現もBasecoatに委ねます。
- 配置・余白・レスポンシブ対応を含む微調整には、Tailwindの既定のクラスを使います。
- コンポーネントは自身の内部レイアウトを定義し、親・兄弟との配置や余白は親側で定義します。
- ブランド表現とBasecoat標準との差分は、各プロジェクトのデザイン資料を参照します。

## 値の指定

- 文字サイズ・色・幅・高さ・余白などは、Basecoatの標準トークンかTailwindの既定値から選びます。
- `text-[13px]`や`gap-[18px]`などの任意値指定は、レイアウト用途も含めて使いません。
- 任意値の代わりに、同じ数値をインラインスタイルや独自CSSへ移す実装もしません。

## 配色

- `text-muted-foreground`や`bg-muted`など、Basecoatの役割に応じた標準トークンを優先します。
- グレースケールを直接指定する場合は、Tailwindの`neutral`に揃えます。`gray`・`slate`・`zinc`・`stone`は使いません。
- 警告やエラーなどの意味を持つ色は、標準variantや`destructive`などの役割トークンを使います。

## フォント

- デフォルトのフォントにはNoto Sans JPを使います。
- 文字サイズは`text-sm`、`text-base`など、Tailwindの標準クラスから選びます。
- 標準文字サイズは`text-sm`、最小の文字サイズは`text-xs`とし、標準の`rem`単位を維持します。

## アイコン

- Tabler Iconsの公式SVGを使い、同じ意味のアイコンを統一します。
- 文字記号・絵文字・CSS図形・独自SVGで代用しません。

## 操作ラベル

- 広い画面では、操作ラベルを「〜する」などの完全な文章で表現します。
- スマホ幅では、操作の意味・対象が分かる範囲で「する」などを省略し、短いラベルにします。
- 広い画面とスマホ幅の区分は、各画面の既存のレスポンシブ設計に従います。
