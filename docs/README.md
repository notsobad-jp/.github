# notsobad-jp 共通開発標準

- notsobad-jpの各リポジトリで共有する開発方針です。

## 参照方法

- セッション開始時に、このページの共通方針と作業ごとの参照先を一度確認します。
- 作業に必要な資料は、その作業の着手前に該当箇所を確認します。
- 複数の条件に該当する場合は、それぞれの資料を参照します。
- 同じセッション内では、内容を把握している資料の再読は不要です。
  - 作業内容が変わった場合や資料が更新された場合は、必要な箇所を追加で確認します。
- プロジェクト固有の仕様・手順は、各リポジトリの資料も参照します。
  - 共通規約と異なる方針は、各リポジトリで明記した差分に従います。

## 共通開発方針

### 既存方針と資料

- 既存例から判断できないルールは利用者に確認し、合意後に該当する規約へ追記します。
- 設計・提供仕様を変える場合は、同じ変更で対応するdocsも更新します。
- 実装・設定・テンプレートの詳細は転記せず、参照で示します。
- 設計・提供仕様はdocs、議論の背景はDiscussion、残作業はIssue、変更とレビューはPRに置きます。
- Markdownの説明は箇条書きを基本とし、必要に応じて階層化します。

### 検証と変更の提出

- 開発環境と検証コマンドは各リポジトリのREADMEを参照します。
- 検証の失敗をフックの無効化やチェックの省略で回避せず、原因を解消するか利用者へ不足を伝えます。
- テストの選択・追加は[テスト方針](testing.md)に従います。

## 作業ごとの参照先

| 作業・参照条件 | 参照先 | 確認する内容 |
| --- | --- | --- |
| 構成・レイヤーの責務・依存関係、Repository・DBスキーマを設計・変更する | [architecture.md](architecture.md) | 配置・命名、レイヤー間の参照、業務の表現、永続化の規約 |
| TypeScript・JSONや、そのコード例を追加・変更する | [typescript.md](typescript.md) | プロパティ順序、Zodモデル、復元・作成・操作の区別 |
| Web画面・コンポーネント・アイコンを追加・変更する | [ui.md](ui.md) | Basecoat UI、配置と余白、アイコン、情報階層とレスポンシブ対応 |
| 変更の検証方法を選ぶ、テストを追加・変更・削除する | [testing.md](testing.md) | 単体・結合テストの分担、保証範囲、CIコストとの比較 |
| 共通Biome・TypeScript設定を導入・更新する、利用側の設定を変更する | [共通設定](../packages/config/README.md) | バージョン、設定の継承、プロジェクト固有の上書き、更新時の検証 |
| 共通CIを導入・更新する、呼び出し側のworkflowを変更する | [共通CIの利用](../README.md#共通ciの利用) | 呼び出し方、参照SHA、利用側で用意するファイル・設定 |

## 各リポジトリのAGENTS.md

- 次の指示と、プロジェクト固有の資料・スキルの作業ごとの参照先を置きます。
- 共通の参照条件はこのページ、規約や手順の本文はリンク先で管理し、AGENTS.mdには転記しません。

```md
- セッション開始時に[共通開発標準](https://github.com/notsobad-jp/.github/blob/main/docs/README.md)を確認し、共通方針と作業内容に応じた資料に従ってください。
```
